# V17 · PRINCIPLES — Ray Dalio
Tier 4 · Founder Judgment · Tree Memory

## ROOT — the deepest truth
Treat your life and company as a MACHINE observed from above: encode every hard-won lesson as an explicit, written, testable principle — so that decisions stop being one-off improvisations and become the output of an ever-improving algorithm fed by radical truth and radical transparency.

## TRUNK — core thesis
Dalio built Bridgewater on a simple loop: PAIN + REFLECTION = PROGRESS. Every mistake is data about how reality works; unexamined, it repeats — examined, it becomes a principle. Decisions improve through an IDEA MERITOCRACY: thoughtful disagreement where the best idea wins regardless of rank, weighted by BELIEVABILITY (track record + sound reasoning in THIS domain, not confidence or seniority). The obstacles are two barriers — EGO (the need to be right) and BLIND SPOTS (ways of thinking that literally can't see certain things). The cure: radical open-mindedness — replacing "I'm right" with "how do I know I'm right?" — and the 5-Step Process run as a loop: goals → problems → diagnosis → design → doing.

## BRANCHES & LEAVES

### Branch 1 — Pain + reflection = progress
├─ Pain signals reality disagreeing with your model; the reflex is to avoid it, the profit is in mining it
├─ The quality question after every setback: "what is this pain teaching me about how reality works?"
└─ LEAF: convert every founder setback into a written principle ("when X conditions, do/never do Y") — the principle is the compensation for the pain

### Branch 2 — The 5-Step Process (the loop)
├─ 1. Goals: clear, prioritized (you can have almost anything, not everything)
├─ 2. Problems: identify precisely, don't tolerate them (tolerated problems = accepted decay)
├─ 3. Diagnosis: root cause — keep asking what the problem is a SYMPTOM of; usually lands on a person/design weakness, often the founder's own
├─ 4. Design: change the MACHINE (roles, processes, rules), not just the instance
├─ 5. Doing: execute with discipline; then loop
├─ Most people fail at 3 → 4: they fix instances forever instead of redesigning the machine that produces them
└─ LEAF: when the same problem appears twice, forbid instance-fixing; demand the machine-level redesign

### Branch 3 — Ego barrier & blind spot barrier
├─ Ego: the deep-brain need to be right hijacks the discussion; being WRONG well is the skill
├─ Blind spots: each thinking style misses things (the visionary misses details; the operator misses paradigm shifts) — permanently
├─ Cure: triangulate with believable people who see what you can't; disagreement is a gift, not an attack
└─ LEAF: for big calls, require ONE believable dissenting view on record before deciding — the goal isn't consensus, it's stress-tested conviction

### Branch 4 — Believability-weighted input
├─ Not all opinions are equal: weight by (a) repeated success in THIS domain, (b) ability to explain the causal logic
├─ Democracy of ideas fails (noise wins); dictatorship fails (blind spots win); meritocracy of believability outperforms both
└─ LEAF: when a founder quotes advice, score the source: domain track record? causal reasoning shown? — an investor's opinion on ops may deserve near-zero weight

### Branch 5 — Principles as algorithms
├─ Write decision rules explicitly enough that they could (in principle) be coded; vagueness hides from testing
├─ Bridgewater encodes investment principles as literal algorithms; humans handle the novel, rules handle the recurring
└─ LEAF: the founder's rulebook should grow monthly; recurring decision types (pricing exceptions, discount requests, hiring bars) belong in rules, freeing judgment for the genuinely new

### Branch 6 — The machine view from above
├─ See yourself as a designer INSIDE the machine you're building, not just a worker in it
├─ Compare outcomes to goals: gaps indict the machine design (people × culture), not just effort
└─ LEAF: schedule the founder's 'designer hour': weekly, above the machine, asking what design change would make this week's problems impossible

## FRUIT — how SmartDecigen applies this
- WHEN a decision review completes (worked/didn't) → APPLY principle extraction: crystallize the lesson as a written if-then rule in the founder's growing rulebook.
- WHEN the same problem recurs → APPLY machine-level diagnosis: what design (process, role, rule) makes this problem structural, and what redesign removes it?
- WHEN the founder seeks validation → APPLY ego-barrier bypass: present the strongest believable disagreement first, then let them decide.
- WHEN advice sources conflict → APPLY believability weighting: rank by domain track record + causal transparency; show the ranking.
- WHEN goals multiply → APPLY step-1 discipline: almost anything, not everything — force the priority order.

## SEEDS — injectable one-liners
- "Pain + reflection = progress. What did this one teach?"
- "You've fixed this instance twice. Time to fix the machine that makes it."
- "How do you know you're right — and who believable disagrees?"
- "Weight the advice by track record in THIS domain, not by confidence."
- "Write the rule so clearly a machine could follow it. Then you'll see if it's true."
